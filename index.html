六个特点

先明确怎么做，再决定用什么。

把目标、材料、模型和工具组织成可继续引导的工作过程。

01

从目标开始的引导

普通对话、WorkCoder、专业工作与创作各有入口。按步骤填写目标、选择目录和材料，确认后开始；执行中可以继续对话调整方向。

专业工作先生成可编辑草稿，由你确认发送；引导填写本身不调用模型。

02

把专业方法带进任务

内置销售、营销、客户支持、产品管理、效率管理、数据分析、财务、法律、生物研究、企业搜索和插件定制 11 个领域。选择当前需要的技能与命令。

专业插件按需启用。材料可以来自本地文件或已授权连接器；选择领域不会自动连接外部账号。

03

模型各有分工，也由你指定

WorkCoder 将执行、只读研究和顾问审查分开。主模型推进任务，研究模型查资料，顾问在计划确定前、重复错误和完成前介入。

依据 ZenMux 公开价格提供轻量、均衡、深度成本档建议，可手动覆盖。不绑定 Claude 型号；成本档不等于能力排名。

04

在工作区里完成实际工作

源码 IDE 提供文件、搜索、Git 和终端；创作覆盖图像、视频、幻灯片与协同设计。设计先明确用途、内容和视觉规则，再预览与局部修改。

浏览器分析可选启用 Chrome DevTools，调用性能、网络、内存等诊断工具；电脑控制也由你按需开启并授权。

05

管理开销，让过程可观察

结合 TokenEconomizer 的本地经验复用、工具按需发现与重复失败提醒，配合有限重试、历史维护和工具输出精简，减少重复工作。

研究探针默认关闭，可开启查看图表并导出 JSON / CSV。实际用量随模型和任务变化，不承诺固定节省比例。

06

离开桌面，也能续接任务

微信配对后，在专属目录中通过 /goal 引导长程任务，查看进度、补充文字和附件、确认权限并接收文件。桌面保留同一任务与工作区。

支持 SSH / WSL 远程工作区与定时任务。桌面需运行；设置中的“保持电脑运行”可阻止自动休眠，但不阻止合盖或手动睡眠。

工程开发，有一条清楚的路线

专业工作 → 工程开发流程：25 个技能、9 个命令。可以从当前阶段进入，也可让 Meta Skill 选择适用技能；测试与发布结论仍须用实际证据确认。

功能一览

从编程到创作，从桌面到微信，按任务选择所需能力。

  • 引导式入口：普通对话、WorkCoder、专业工作与创作，先明确目标、目录和材料。
  • 源码 IDE：文件浏览、搜索、Git 与终端，围绕本地项目修改和验证。
  • WorkCoder：执行、只读研究、关键节点顾问审查，可自选角色模型。
  • 专业与工程向导：11 个专业领域，需求、规划、实现、测试、审查、发布六阶段。
  • 创作工作区：图像、视频、幻灯片与协同设计，支持预览和局部修改。
  • 微信长程任务：专属目录、/goal、权限确认、途中引导、附件补充与成果回传。
  • 模型与用量：ZenMux 模型选择、支持的思考档位、TokenEconomizer 与重复失败提醒。
  • 研究探针：按需开启数据记录、图表查看与 JSON / CSV 导出，默认关闭。
  • 电脑与浏览器：可选原生 Computer Use、内置浏览器与 Chrome DevTools 性能和网络诊断。
  • 自动化与远程：定时任务、SSH / WSL 工作区，以及三大桌面平台的保持唤醒设置。

专属工作区，分步启动长程任务

使用 /wechat 进入微信专属目录，/goal 分步填写目标与验收要求，确认后启动；支持查看状态、暂停和继续。

默认模型与思考强度，由你设定

在设置中按微信账号选择文本模型与思考强度。微信发送 /think 或 /思考 查看支持档位；普通任务沿用文本模型，仅生图使用图像模型。

权限确认支持本任务 Yolo

首次目标确认或权限询问时，可显式选择本任务 Yolo。也可单次允许、按请求范围始终允许或拒绝；回复不完整时会提示完整确认码。

PDF 与图片，作为附件交付

生成结果通过微信文件或图片消息回传，不以本地路径链接代替送达。生图默认使用系统图像模型，也可显式指定单次模型。

续问与补充材料，回到原任务

修复冷启动续问时的会话模型读取。运行中补发附件进入当前任务队列；普通续问与权限事件不再覆盖待回传的 PDF 记录。

清空范围明确，删除前再确认

/clean 或 /清空 仅清空微信专属目录，必须二次确认；运行中的目录不能清空。/clear 仍表示新建对话，不会删除工作区文件。

工作流ZenCode分散工具流程
手机续接微信配对桌面 Host，消息进入同一任务和会话。若聊天、远程桌面和创作工具彼此独立，用户需要在应用间切换并自行衔接任务上下文。

定时任务由桌面应用本机调度，需保持 ZenCode 运行且电脑唤醒。开启设置中的“保持电脑运行”可在会话执行期间防止闲置休眠，但不能阻止合盖或手动睡眠；错过计划时间 5 分钟及以上的任务可能跳过。

常见问题

常见问题

使用 ZenCode 要花钱吗？

ZenCode 连接 ZenMux。你需要自己的 API Key，可使用订阅或按量付费 Key；模型覆盖、配额与费用以 ZenMux 账户和套餐规则为准。通过本页邀请链接注册 ZenMux，作者可能获得推广奖励或额度；价格、奖励资格及结算以 ZenMux 现行规则为准。

ZenMux 邀请注册（可选） · ZenMux 计费规则

文件和密钥会发到哪里？

文件保留在对应工作区，API Key 加密保存在本机。模型请求会发送到 ZenMux。

调度模型会自动创建子 Agent 吗？

不会。调度模型为新任务选择执行模型；子 Agent 的创建由当前任务和用户控制。

切换模型一定能节省 Token 吗？

不能保证固定节省。工具输出精简会保留可找回的原文，会话也可共享已提交历史；实际 Token、费用与缓存效果仍取决于内容及模型供应商。

支持哪些平台？

macOS Apple Silicon、Windows x64/ARM64、Linux x64/ARM64；Linux 提供 DEB 和 RPM。

ZenCode 的源码在哪里？

ZenCode 产品源码。产品基于开源 ZCode 开发；Landing Page 源码在 ZenMuxDev。

支持 Intel Mac 吗？

目前没有 Intel Mac 安装包；macOS 正式下载仅支持 Apple Silicon。
