# 输入框控制开关

## 产品规则

- 「控制电脑」与「控制浏览器」的选中态只代表当前工作区对应插件的实际启用状态。插件未加载、未安装或启用失败时，按钮不能保持虚假的选中外观。
- 浏览器按钮文案明确为「控制内置浏览器」，避免暗示可直接接管 Brave 等外部浏览器。
- 输入框挂载时按工作区身份加载插件概览；加载中不允许切换。插件缺失时显示当前构建未提供该能力的原因。浏览器控制仅适用于内置浏览器；电脑控制依赖原生插件和系统授权。
- 启停成功后由插件管理 store 更新状态；运行中的会话不会因为 UI 局部状态误显示可用。失败原因在输入框附近可见，允许用户重试。

## 状态与接口

- `pluginManagementStore` 是插件启用状态的唯一所有者；composer 仅订阅它并调用现有 `initialize` / `setEnabled` 接口。
- 工作区 key 采用 `workspaceIdentity?.trim() || workspacePath`。初始化和异步启停结果由 store 处理，composer 不保留第二份开关真值。
- 不改变 CLI 的工具注册、Helper 权限和插件打包边界；缺少原生运行时不能被 UI 伪装成可用。

```text
工作区进入 → composer 请求 initialize → pluginManagementStore → 插件服务/CLI
                                      ← 概览成功或失败 ←
用户点击 → store.setEnabled → 插件服务/CLI → store 确认或回滚 → 按钮重绘
```

## 验收场景

1. 插件概览尚未加载或目标插件缺失：对应按钮未选中，不能把点击当作成功启用。
2. 插件启用失败：按钮回到 store 的实际状态，显示失败原因。
3. 插件启用成功：按钮与 store 保持一致；切换工作区后刷新并显示目标工作区状态。
4. 浏览器插件可用、电脑插件缺失：浏览器按钮可操作，电脑按钮解释其不可用原因。
